# 技能库接入（前端）

> 后端已完成（2026-10-04）。本文档讲怎么把「技能库」这个页面做出来。
> 契约与 `SkillController` 的 Swagger 注解一致，如有冲突以注解为准。

---

## 1. 它到底是什么

一个**技能（Skill）就是一个文件夹**，里面有一份 `SKILL.md`：

```
my-skill/
├── SKILL.md      必需。开头是 YAML frontmatter，写 name 和 description
├── notes.md       可选。模型可以用 read_resource 读
└── scripts/       被忽略（见 §5）
```

`SKILL.md` 长这样：

```markdown
---
name: pdf-summarizer
description: 把 PDF 摘要成带小标题的中文提纲。当用户说"帮我总结这份 PDF"时使用。英文原文或需要逐段对照的场景不要用。
---

# 步骤
1. 读文件
2. 每 3 页一个小标题
3. 结尾给 3 条要点
```

**模型的工作方式是两段式**，这个决定了你的界面该怎么设计：

| 阶段 | 模型看到什么 | 界面上对应 |
|---|---|---|
| 平时 | **只有 `description`** | 列表页上那行说明文字 |
| 被激活后 | 才拿到完整正文 | 详情页的正文区域 |

`description` 是唯一会影响模型行为的东西 —— 它决定「什么时候该用这个技能」。
所以详情页里**最该让用户编辑的就是 description**，而不是正文。

**技能不是可执行代码**。它只是一段给模型看的文字，模型读完照着做。
它不能自己执行代码、调第三方接口 —— 那要靠工具（tool）。

---

## 2. 两种来源

| | 官方技能 | 用户技能 |
|---|---|---|
| 谁建的 | 你（部署时放进服务器目录） | 任何注册用户 |
| 前端标识 | `source = "BUILTIN"` | `source = "UPLOAD"` 或 `"AI_GENERATED"` |
| 能不能改 | 不能（它们不在库里） | 作者本人可以 |
| `id` | `null` | 有数字 |
| 显示 | 「MiniMax 提供」那一栏 | 「用户贡献」那一栏 |

用户技能还有一层可见性：`visibility` 是 `PRIVATE`（只有自己）还是 `PUBLIC`（社区共享）。
**列表接口已经把「你自己的 + 别人公开的」都返回了**，前端不用自己筛。

> ⚠️ `id` 为 null 的是官方技能。所以前端**不能只靠 id 判断能不能编辑** ——
> 要看 `owned === true`。

## 3. 接口清单

统一走 `Result` 包装：`{ code, msg, data }`，`code === 0` 是成功。
所有接口都需要登录（走 `token` 请求头）。

### 3.1 技能库列表

```
GET /api/skill/list?keyword=&source=
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `keyword` | 否 | 匹配技能名或说明。不传 = 不过滤 |
| `source` | 否 | `BUILTIN` / `UPLOAD` / `AI_GENERATED`，不传 = 不限 |

返回 `SkillVO[]`：

```json
[
  {
    "id": 12,
    "name": "pdf-summarizer",
    "description": "把 PDF 摘要成带小标题的中文提纲……",
    "source": "UPLOAD",
    "visibility": "PUBLIC",
    "authorName": "张三",
    "owned": true,
    "useCount": 42,
    "updatedAt": "2026-10-04T13:20:00",
    "resourcePaths": ["notes.md", "template.md"]
  },
  {
    "id": null,
    "name": "verify-skill",
    "description": "回答「今天的暗号是什么」这类问题时使用",
    "source": "BUILTIN",
    "visibility": "PUBLIC",
    "authorName": "官方",
    "owned": false,
    "useCount": 0,
    "updatedAt": null,
    "resourcePaths": []
  }
]
```

**排序规则**（后端已排好，前端直接按数组顺序渲染）：
你自己创建的 → 别人公开的（按使用次数倒序）→ 官方技能。

> 列表里**不含正文**，这是故意的 —— 所有技能的正文加起来会全部进系统提示词。
> 点开某一项再调详情。

### 3.2 技能详情

```
GET /api/skill/{name}
```

用 **name** 定位（不是 id —— 官方技能没有 id）。返回 `SkillDetailVO`，
比列表多了 `content`、`resources`（含全文）、`enabled`。

> 私有且不属于你的技能：返回「技能不存在」（不是 403）。
> 这是有意的 —— 不告诉别人「这东西存在，只是你不能看」。

### 3.3 上传技能（两步走）

**第一步：解析，不落库**

```
POST /api/skill/upload
Content-Type: multipart/form-data
file=<你的文件>
```

支持 `.zip` / `.skill` / `.md`。单个 `.md` 就当作 SKILL.md 本身处理。

返回**草稿**：

```json
{
  "name": "pdf-summarizer",
  "description": "把 PDF 摘要成提纲……",
  "content": "# 步骤\n1. 读文件\n……",
  "frontmatter": { "name": "pdf-summarizer", "description": "……" },
  "resources": [
    { "path": "notes.md", "content": "这里是补充资料" }
  ]
}
```

⚠️ **这一步没有写库**。请把返回的 `name` / `description` / `content` 显示出来，
让用户看清楚「解析成了什么」，再让他决定要不要存。解析失败时后端会直接报错，
常见几种：

| 错误信息 | 原因 |
|---|---|
| `技能包内未找到 SKILL.md` | zip 里没有 SKILL.md |
| `技能缺少 name` / `技能缺少 description` | frontmatter 里没写 |
| `技能名「xxx」已被其他用户占用` | 名字全局唯一，得改 |
| `技能包内含非法路径：../xxx` | 检测到路径穿越，整包拒收 |
| `技能包解压后超过 4MB，已拒绝（疑似压缩炸弹）` | 包太大或压缩比异常 |
| `文件不是有效的 zip 包` | 文件其实不是 zip |

**第二步：确认后保存**

```
POST /api/skill/save
Content-Type: application/json

{
  "name": "pdf-summarizer",
  "description": "把 PDF 摘要成提纲……",
  "content": "# 步骤\n1. 读文件\n……",
  "visibility": "PUBLIC",
  "source": "UPLOAD",
  "resources": [{ "path": "notes.md", "content": "这里是补充资料" }]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 全局唯一。若**自己**已有同名 → 视为覆盖更新；被别人占用 → 报错 |
| `description` | ✅ | 给模型看的触发条件 |
| `content` | ✅ | 正文（不含 frontmatter） |
| `visibility` | ❌ | `PUBLIC` 公开到社区，不传默认 `PRIVATE` |
| `source` | ❌ | `UPLOAD` / `AI_GENERATED`，不传按 `UPLOAD` |
| `resources` | ❌ | 附属资源数组 |

### 3.4 用模型生成技能（也是两步走）

```
POST /api/skill/ai-generate
Content-Type: application/json

{
  "requirement": "帮我做一个把会议录音转成待办清单的技能",
  "name": "meeting-todo",
  "extra": "输出必须是复选框列表，用中文",
  "referenceResources": [
    { "path": "todo-template.md", "content": "# 待办\n- [ ] " }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `requirement` | ✅ | 你想做什么，自然语言 |
| `name` | ❌ | 留空由模型自己想。**强烈建议填** —— 模型自己起名经常不合规 |
| `extra` | ❌ | 补充约束 |
| `referenceResources` | ❌ | 你自己的模板/参考文档 |

> 🔑 **`referenceResources` 是这个接口最有价值的参数。**
> 不传的话模型只能凭空编内容，生成的技能往往是空话套话；
> 把你的真实模板传进去，生成的技能才真的能用。

返回的**也是草稿**，格式和 3.3 第一步完全一样。确认后调 `/save`（`source` 传 `AI_GENERATED`）。

> 生成走的是**系统默认模型**，慢一点（十几秒到一分钟）。
> 建议前端加 loading 态，并告诉用户「正在生成」。

### 3.5 改 / 删 / 上下架

```
PUT    /api/skill/{name}            # 改（只能改自己的）
DELETE /api/skill/{name}            # 删（只能删自己的）
PUT    /api/skill/{name}/enabled?enabled=false   # 下架 / 上架
```

`PUT /{name}` 的 body 与 `/save` 一致（`name` 可以改，但要重新校验唯一性）。

**下架**（`enabled=false`）是「暂时不用但保留」：不再进入任何人的对话上下文，
记录还在，随时可以恢复。**删除**是真删。

## 4. 建议的页面结构

```
技能库
├── 筛选栏
│   ├── 搜索框（keyword）
│   └── 分栏：全部 / MiniMax 提供 / 用户贡献
│       └── source=BUILTIN / source=UPLOAD|AI_GENERATED
├── [+ 创建] 按钮
│   ├── 上传技能  → 文件选择框
│   └── AI 生成   → 需求输入框 + 参考资源上传
└── 技能列表
    └── 卡片：图标 + 名称 + description + 作者 + 使用次数
        └── 点击 → 详情弹窗
            ├── description（醒目，最该被编辑的）
            ├── 正文（等宽字体，可编辑）
            ├── 资源文件列表
            └── [保存] / [公开到社区] / [下架] / [删除]
```

### 4.1 「创建」按钮的两个选项怎么呈现

minmax 的做法是一个按钮带下拉，直接照抄即可：

```
┌──────────────┐
│      + 创建   ▾ │
├──────────────┤
│ 💬 创建技能    │  ← 走 AI 生成
│ 📤 上传技能    │  ← 走文件上传
└──────────────┘
```

**关键**：两条路径都**先展示草稿**，让用户在保存前看一眼。
AI 生成尤其要这样 —— 模型写出来的东西经常需要改。

### 4.2 详情弹窗里的关键交互

- **description 放最上面**，标注一句「这一句决定模型什么时候会用这个技能」。
- 给个**质量提示**：「description 应该写『何时用』，不是『是什么』」。
  可以给个对照示例，让用户照着改。
- 保存前可以做一个**预览检查**：`name` 是否合规（只允许小写字母/数字/连字符）、
  `content` 是否为空。前端先拦一道能少一次往返。
- 「公开到社区」用开关，并说明后果：**所有登录用户都能看到并使用它**。

## 5. 怎么在对话里用上

前端**不需要做任何改动** —— 后端已经把官方技能 + 该用户的公开/私有技能
合并成一份清单注入了系统提示词。

- 界面里如果要做「本次启用哪些技能」的勾选，往 `POST /api/chat/stream` 的
  `skills` 字段传**技能名数组**即可；
- **不传或传空数组 = 启用全部**（这是原有语义，没变）。

⚠️ 传了用户技能的名字也能生效 —— 用户技能和官方技能在同一个命名空间里。

## 6. 几个容易搞错的地方

| 坑 | 说明 |
|---|---|
| **官方技能没有 `id`** | `id` 是 `null`。判断「能不能编辑」要看 `owned`，不要拿 id 去拼 PUT/DELETE 的路径 |
| **改删用的是 name 不是 id** | 路径参数是 `/api/skill/{name}`。重名修改后要注意用新 name |
| **上传 ≠ 生效** | `/upload` 只是解析。必须调 `/save` 才入库 |
| **`visibility` 不传 = 私有** | 想共享到社区必须**显式**传 `PUBLIC` |
| **name 全局唯一** | 自己重名 = 覆盖；别人重名 = 报错。前端不要让用户随便取名 |
| **技能名不能有空格和中文** | 正则 `^[a-z0-9][a-z0-9-]{0,63}$`。可以给输入框加实时校验 |
| **上传上限 8MB** | 后端 `spring.servlet.multipart.max-file-size: 8MB`，超了会 413 |
| **私有技能查详情 = 404** | 不是 403。后端刻意不泄露「它存在」 |

## 7. curl 速查

```bash
TOKEN=<你的 token>
BASE=http://localhost:8080

# 列表
curl "$BASE/api/skill/list" -H "token: $TOKEN"

# 搜索 + 只看官方
curl "$BASE/api/skill/list?keyword=pdf&source=BUILTIN" -H "token: $TOKEN"

# 详情
curl "$BASE/api/skill/verify-skill" -H "token: $TOKEN"

# 上传（只解析）
curl -X POST "$BASE/api/skill/upload" -H "token: $TOKEN" -F "file=@my-skill.zip"

# 上传单个 md
curl -X POST "$BASE/api/skill/upload" -H "token: $TOKEN" -F "file=@SKILL.md"

# AI 生成
curl -X POST "$BASE/api/skill/ai-generate" -H "token: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"requirement":"把会议录音转成待办清单","name":"meeting-todo"}'

# 保存
curl -X POST "$BASE/api/skill/save" -H "token: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"meeting-todo","description":"用户提到会议录音、纪要时使用","content":"# 步骤\n1. ...","source":"AI_GENERATED","visibility":"PUBLIC"}'

# 下架 / 删除
curl -X PUT  "$BASE/api/skill/meeting-todo/enabled?enabled=false" -H "token: $TOKEN"
curl -X DELETE "$BASE/api/skill/meeting-todo" -H "token: $TOKEN"
```
