# 模型能力配置（给前端）

> 适用范围：前端的「模型管理 / API 配置」界面。
> 相关后端改动：2026-10-03（commit 见仓库 log），**不需要改数据库**。

---

## 1. 一句话

用户在配置 API Key 时，给每个模型**额外填三个字段**：

| 字段 | 类型 | 默认值 | 作用 |
|---|---|---|---|
| `vision` | boolean | `false` | 这个模型能不能看图。勾了才会把图片发成真图 |
| `contextWindow` | number | `256000` | 上下文窗口（token），用来裁剪历史 |
| `maxOutputTokens` | number | `32000` | 单次最大输出 token |

**不填就是默认值**，老数据不受任何影响（这三个字段存在 `user_config.llm_api_token` 这个 jsonb 列里，加字段不用改表）。

---

## 2. 存在哪：就在原来的模型数组里

保存 API 配置走的还是老接口 `POST /api/user/api-config`，请求体里的 `model` 数组每个元素多加三个字段即可：

```jsonc
{
  "id": "xEzqaQFgFv1",
  "name": "阿里云百炼",
  "APIKey": "sk-xxxxxx（密文由后端返回，前端不要自己加密）",
  "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1",
  "model": [
    {
      "name": "qwen3-vl-plus",
      "type": "CHAT",
      "vision": true,            // ← 新增：这个模型支持看图
      "contextWindow": 262144,   // ← 新增：可不填，默认 256000
      "maxOutputTokens": 32768   // ← 新增：可不填，默认 32000
    },
    {
      "name": "qwen3-max",
      "type": "CHAT"
      // 三个字段都不写 = vision:false, 256000, 32000
    },
    {
      "name": "text-embedding-v4",
      "type": "EMBEDDING"
    }
  ],
  "isDefault": true
}
```

`GET /api/user/api-config` 会原样把这三个字段带回来（后端解密后返回的是脱敏 Key，模型数组原样透传）。

---

## 3. 三个字段分别影响什么

### `vision` —— 决定图片怎么发给模型

| 值 | 行为 | 模型表现 |
|---|---|---|
| `true` | 图片发成真正的 `image_url` | 多模态模型**真的能看到画面** |
| `false`（默认） | 图片降级成「一段带 URL 的文本」 | 模型知道有张图但看不到，只能靠你描述 |

⚠️ **为什么默认 false**：不支持视觉的模型收到 `image_url` 会被上游 API 直接拒绝（400/报错），
而"降级成文本"最坏只是看不到图。**宁可降级，不要报错。**

所以前端的勾选项建议写成：

```
[ ] 支持图片输入（视觉）
    ↑ 默认不勾。给 qwen-vl / gpt-4o / claude 这类模型勾上
```

### `contextWindow` —— 决定带多少历史进提示词

后端算的是：

```
本次能用的历史 token = min(
    全局上限 nexus.agent.memory.max-tokens,
    contextWindow − maxOutputTokens
)
```

默认 256000 − 32000 = **224000** 的历史预算。

- 模型窗口小（比如 8k），不填会**超出窗口被上游拒绝** → 要填真实值
- 模型窗口大（比如 1M），填了才会用满；不填就按 256k 走（保守，不会出错）
- 填错成「输出比窗口还大」也没事，后端保底给 2048 token，不会把历史裁光

### `maxOutputTokens` —— 决定模型单次最多回多少

直接作为 `max_tokens` 发给模型。不填 32000。

## 4. 前端要做的改动清单

1. **模型编辑表单**加两个输入框 + 一个勾选框：
   - 上下文窗口（number，placeholder `256000`，可留空）
   - 最大输出 token（number，placeholder `32000`，可留空）
   - 支持图片输入（checkbox，默认**不勾**）
2. 提交时按上面的 JSON 结构带上，留空就**不要传这个字段**（或传 null），后端会按默认处理
3. 展示层可以做的小优化（非必需）：
   - 勾了视觉的模型，在模型选择器上标个「👁 支持图片」之类的标记
   - 用户给不支持视觉的模型发图时，提示一句「当前模型不支持看图，已降级为链接」

## 4.5 系统内置模型（后端配的，前端只管列出来）

后端可以在 `application-prod.yml` 里配多个**系统内置模型**（给没配自带 Key 的用户用）。
结构：**一家供应商一项**（`baseUrl` + `apiKey` 只写一次），**该项下 `models` 挂多个模型**：

```yaml
nexus:
  agent:
    system-models:
      - id: deepseek
        name: DeepSeek
        baseUrl: https://api.deepseek.com
        apiKey: ${DEEPSEEK}
        models:
          - id: deepseek-chat
            name: DeepSeek-V3
            modelName: deepseek-chat
            contextWindow: 131072
            maxOutputTokens: 8192
          - id: deepseek-reasoner
            name: DeepSeek-R1
            modelName: deepseek-reasoner
      - id: qwen
        name: 阿里云百炼
        baseUrl: https://dashscope.aliyuncs.com/compatible-mode/v1
        apiKey: ${ALI_AI_KEY}
        models:
          - id: qwen3-max
            name: 通义千问-Max
            modelName: qwen3-max
          - id: qwen-vl
            name: 通义千问-VL（支持看图）
            modelName: qwen-vl-max
            vision: true
```

- 模型级没填的 `vision` / `contextWindow` / `maxOutputTokens` → **继承供应商级** → 再用默认值
- 旧写法（一项 = 一个模型，`modelName` 直接写在供应商上）也仍然支持

前端用 **`GET /api/chat/models`** 拿到可选项（**扁平列表**，一家供应商会展开成多条）：

```jsonc
[
  { "id": "deepseek-chat",     "name": "DeepSeek-V3", "modelName": "deepseek-chat",
    "vision": false, "contextWindow": 131072, "maxOutputTokens": 8192,
    "providerId": "deepseek", "providerName": "DeepSeek" },
  { "id": "deepseek-reasoner", "name": "DeepSeek-R1", "modelName": "deepseek-reasoner",
    "vision": false, "contextWindow": 256000, "maxOutputTokens": 32000,
    "providerId": "deepseek", "providerName": "DeepSeek" },
  { "id": "qwen-vl", "name": "通义千问-VL（支持看图）", "modelName": "qwen-vl-max",
    "vision": true, "providerId": "qwen", "providerName": "阿里云百炼" }
]
```

- 用 `providerId` / `providerName` 就能在 UI 上按供应商分组展示
- **列表为空** = 后端没启用这项配置（此时只有 langchain4j 配的那一个默认模型）
- **不含密钥**
- 发起对话时 `model.id` 传这里的 `id`；只传 `modelName` 也能匹配上；都匹配不上回退第一项

## 5. 常见误解

- **Q：要改数据库吗？** 不用。模型元数据在 `user_config.llm_api_token` 这个 **jsonb** 列里，加字段对老数据透明。
- **Q：老配置会失效吗？** 不会。老数据没有这三个字段 → 反序列化为 null → 后端按默认值兜底（不视觉 / 256k / 32k）。
- **Q：图片消息的请求体要变吗？** 不变。还是 `messages[].metadata.fileUrl`（驼峰），见 `docs/前端开发指南.md`。
- **Q：系统默认模型（用户没配 Key）支持看图吗？** 按默认处理 = 不支持。要支持就得让用户配置自己的 Key 并在模型上勾视觉。
