# 乐享知识库接入 · 前端对接文档（2026-10-03）

> 面向前端。**本次只做「检索」，不做文件上传** —— 用户的管理与维护仍在乐享侧完成。
>
> 关联：`docs/前端开发指南.md`（通用约定，本文假设你已读过那五件事）。
> 后端实现：`LexiangController` / `LexiangRagTool` / `LexiangTokenProvider`。
>
> **本文字段全部来自真实代码，不是猜的。发现不一致以代码为准并回来改本文。**

---

## 0. 三件必须先知道的事

| # | 事项 | 结论 |
|---|---|---|
| 1 | 这是**只读**接入 | 只有"读凭证 / 写凭证 / 选库 / 测连通"，**没有任何上传接口**。别做上传按钮 |
| 2 | `staffId` 是权限维度 | 它等于乐享的 `x-staff-id`。填自己的成员账号才能检索私有知识；填 `system-bot` 只能检索**全公司公开**的知识 |
| 3 | 知识库检索只有乐享这一条路 | 2026-10-04 起本地知识库（pgvector）已下线，`enableRag` 已删除；现在只要 `enableLexiangRag: true` |

## 1. 完整接入流程

```
① 用户在乐享后台拿凭证  →  ② 填进你的页面  →  ③ 拉团队列表
                                                      ↓
                                    ④ 选团队 → ⑤ 拉知识库列表 → ⑥ 选知识库（设为默认）
                                                      ↓
                                    ⑦ 对话时带 enableLexiangRag=true  →  ⑧ 乐享知识参与回答
```

## 2. 接口清单

统一前缀 `/api/lexiang`。所有接口**都需要登录态**（请求头 `token: <JWT>`）。

### 2.1 保存凭证 `POST /api/lexiang/credential`

用户在乐享【企业管理后台】→【开发】→【接口凭证管理】→ 添加凭证，拿到 `AppKey` / `AppSecret`。

```json
{
  "appKey": "lx_xxxxxxxx",
  "appSecret": "用户填的明文密钥",
  "staffId": "张三",
  "defaultTeamId": "74d76195adxxxxx",
  "defaultSpaceId": "12a0fcf878xxxxx"
}
```

| 字段 | 必填 | 说明 |
|---|:---:|---|
| `appKey` | ✅ | 乐享 AppKey |
| `appSecret` | ✅ | 乐享 AppSecret，**服务端加密后存储** |
| `staffId` | ✅ | 发起检索的成员账号，即 `x-staff-id`。不填默认 `system-bot`（只能搜公开知识） |
| `defaultTeamId` | ❌ | 默认知识库所属团队 |
| `defaultSpaceId` | ❌ | 默认检索的知识库。**不填 = 检索全站** |

响应：`{code:1, msg:"成功"}`

> ⚠️ 重复保存即**覆盖**（一个用户只保留一份配置）。
> ⚠️ 保存成功后后端会**作废旧的 token 缓存**，所以改完凭证立即生效，不需要等 2 小时。

---

### 2.2 读取凭证 `GET /api/lexiang/credential`

**响应体刻意不含 AppSecret**，只给一个布尔值：

```json
{
  "code": 1, "msg": "成功",
  "data": {
    "appKey": "lx_xxxxxxxx",
    "secretSaved": true,
    "staffId": "张三",
    "defaultTeamId": "74d76195adxxxxx",
    "defaultSpaceId": "12a0fcf878xxxxx"
  }
}
```

未配置时 `data` 为 `null`。

**UI 建议**：`secretSaved === true` 时，AppSecret 输入框**留空并显示占位符**（如"已配置，留空表示不修改"），
留空即表示不改动 —— 这样用户回填其他字段时不会误把密钥清空。

---

### 2.3 列团队 `GET /api/lexiang/teams`

```json
{ "code": 1, "data": [ { "id": "74d7...", "name": "研发中心" } ] }
```

乐享的层级是 **team → space → entry**，所以**必须先有 teamId 才能列知识库**。

---

### 2.4 列知识库 `GET /api/lexiang/spaces?teamId=xxx`

```json
{
  "code": 1,
  "data": [
    {
      "id": "12a0fc...",
      "name": "产品需求库",
      "logo": "https://...",
      "teamId": "74d7...",
      "url": "https://lexiangla.com/spaces/12a0fc..."
    }
  ]
}
```

`url` 可直接跳回乐享，做"去乐享查看"的链接。

> ⚠️ 知识库能列出来，取决于**管理员发 AppKey 时选的授权范围**。
> 只绑了特定团队的 AppKey，在这里就看不到其他团队的库 —— 这不是 bug。

---

### 2.5 设为默认 `PUT /api/lexiang/space?spaceId=xxx&teamId=xxx`

只改检索范围，**不触碰 AppSecret**。两个参数都是 query 参数。

---

### 2.6 连通性测试 `POST /api/lexiang/test?staffId=xxx&spaceId=xxx`

两个参数都可省略（省略则用已保存的默认值）。**会真实调一次乐享检索**，返回命中条数：

```json
{ "code": 1, "data": 3 }
```

**这个接口会真实暴露以下问题**（比只换 token 可信得多）：

| 报错信息 | 原因 | 用户该做什么 |
|---|---|---|
| `AppKey 无效` | AppKey 填错 | 去乐享后台核对 |
| `AppSecret 错误` | AppSecret 填错 | 重新填写 |
| `获取凭证过于频繁（乐享限制 20 次/10 分钟）` | 短时间内点了多次测试 | 稍等再试 |
| `没有权限访问该知识库` | AppKey 授权范围不含该库 | 让管理员改授权范围，或换一个库 |
| `凭证已失效，请重新保存` | token 过期且重取失败 | 重新保存凭证 |

**UI 建议**：保存凭证后自动调一次 test，失败就地把原因显示在表单下方，别只弹"保存失败"。

## 3. 对话时怎么用（唯一的必改点）

### 3.1 请求体加一个字段

`POST /api/chat/message` 的 body 里**新增** `enableLexiangRag`：

```json
{
  "messages": [ { "role": "user", "content": "报销流程是什么" } ],
  "sessionId": "xxx",
  "model": { "modelName": "deepseek-chat" },
  "enableLexiangRag": false,
  "enableLexiangRag": true
}
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| ~~`enableRag`~~ | — | — | ★已删除（2026-10-04）：本地 pgvector 知识库已下线，后端不再接受该字段 |
| `enableLexiangRag` | boolean | false | **本次新增**：乐享知识库 |

两个开关**互不影响**：

| 场景 | `enableRag` | `enableLexiangRag` | 效果 |
|---|:---:|:---:|---|
| 都不用 | ❌ | ❌ | 纯对话，最快 |
| ~~只用本地库~~ | — | — | ★已无此场景（本地库已下线） |
| 只用乐享 | ❌ | ✅ | 检索企业的乐享库 ← **本次主场景** |
| 都用 | ✅ | ✅ | 两个库都检索，结果合并喂给模型 |

> **不传 `enableLexiangRag` 等于 false**，旧前端不受影响，可以先不急着改。

### 3.2 检索是模型自动触发的

前端**不需要**自己调检索接口。后端注册了 `lexiang_search` 工具，模型判断需要时会自己调。

工具的返回会拼成下面这样喂给模型（**你不需要处理**）：

```
以下是检索到的资料:知识来源:员工手册(链接:https://lexiangla.com/pages/abc)年假需提前 3 天申请--------结束---------
```

因为结果里带了 `url`，模型能在回答里给出**可点击的引用溯源** —— 建议前端把回答里的乐享链接渲染成可跳转样式。

### 3.3 失败不会中断对话

乐享挂了（超限/凭证失效/网络问题）时，工具会**把错误当作工具结果回给模型**，模型会如实告诉用户"乐享知识库检索失败：..."，
**整条 SSE 流不会中断**。你不需要做重试或降级 UI。

唯一例外：**用户没配凭证就开了 `enableLexiangRag`**，此时模型会说"尚未接入乐享知识库"。
所以前端应该**在用户没配置时就不给开这个开关**（或显示"未接入"角标）。

## 4. 鉴权提醒

⚠️ 本项目鉴权头是 **`token: <JWT>`**，不是 `Authorization: Bearer`。

```js
fetch('http://localhost:8080/api/lexiang/teams', {
  headers: { 'token': localStorage.getItem('token') }
})
```

## 6. 我不做的事（省得你找）

- **没有上传接口**。用户要在乐享上加文件，就去乐享上加。
- **没有 AI 问答透传**。答案永远由你自己选模型生成，不走乐享的 `ai/qa`。
- **没有 Webhook / 知识库同步**。乐享内容变更后，靠下一次检索实时拿最新片段。
- **没有 per-space 多库绑定**。一个用户当前只支持一个默认知识库。
